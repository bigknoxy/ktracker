## Feature: MVP Weight, Workout, and Task Management Application

### Description
Develop a Minimum Viable Product (MVP) application for tracking weight, workouts, and tasks. The application should feature a dashboard as its homepage.

### Requirements

- **Core Functionality:**
    - Weight Tracking:
        - Record daily weight entries.
        - Visualize weight changes over time (line graph).
        - Calculate BMI.
        - Set weight goals.
    - Workout Tracking:
        - Log workout sessions (date, time, duration, exercises).
        - Define exercises (name, type - cardio, strength, etc.).
        - Record sets, reps, and weight for each exercise.
        - Track personal bests.
    - Task List:
        - Create tasks with due dates and priorities.
        - Mark tasks as complete.
        - Categorize tasks (e.g., work, personal, fitness).
- **User Interface (Dashboard):**
    - Display current weight.
    - Show recent workout summaries.
    - List upcoming tasks.
    - Provide quick access to add new entries (weight, workout, task).
- **Technical Specifications:**
    - Programming Language: TypeScript
    - Runtime Environment: Bun (not npm)
    - Database: PostgreSQL
    - Data Persistence: Utilize an ORM (e.g., Prisma) for database interactions.
    - API: RESTful API design.
    - Authentication: Basic user authentication (username/password) for MVP.  Expand later.
    - Deployment: Containerization with Docker for easy deployment.
- **Non-Functional Requirements:**
    - Performance: Application should be responsive and load quickly.
    - Scalability: Design with future scalability in mind.
    - Security: Implement basic security measures to protect user data.
    - Maintainability: Write clean, well-documented code.
- **Initial Data Models:**
    - User: id, username, password, email
    - WeightEntry: id, userId, date, weight
    - Workout: id, userId, date, duration
    - Exercise: id, name, type
    - WorkoutExercise: id, workoutId, exerciseId, sets, reps, weight
    - Task: id, userId, title, description, dueDate, priority, completed
- **API Endpoints (Initial):**
    - /users (POST - register)
    - /login (POST - login)
    - /weight (POST - add weight, GET - get weight history)
    - /workouts (POST - add workout, GET - get workout history)
    - /tasks (POST - add task, GET - get task list)
- **Bun Specifics:**
    - Leverage Bun's built-in tools for bundling and transpilation.
    - Utilize Bun's speed advantages for faster development and execution.
- **PostgreSQL Specifics:**
    - Design database schema optimized for querying weight, workout, and task data.
    - Use appropriate data types for each field.
    - Implement indexes for frequently accessed columns.
